What the AI wrote:
- Branch practice-9 from main. src/optimizer.py, the --remove-unused pass,
  and the flag in compiler.py, which runs the pass after the checker.
- Task 1: reads counted per declaration through the checker's decl links;
  dead declarations removed with their assignments; repeated until a round
  removes nothing.
- Task 2: calls counted per global function in the same walk; dead
  functions removed in the same loop.
- Additional task: the set of functions with an effect (print or read(),
  mutating, a while, recursion, or a call of such a function), computed as
  a fixpoint over the call graph. It replaces Task 1's "any call keeps the
  value" rule under the same flag.
- check.py: a tests/opt suite (same output with and without the flag, and
  the tree in .astc) and REMOVE_UNUSED=1, which runs every earlier program
  with the flag.
- tests/opt: 12 programs. The two warm-ups, the three-function chain and
  the effects example are copied from the practice file. The others cover a
  declaration in an if, values kept by a printing call and by read(),
  assignment-only variables and field writes, a program where nothing is
  removed, and the counter, relay, while/recursion and lambda effect cases.
- README: the Optimizations section with both counting limits and the
  memory note, and the tests/opt and REMOVE_UNUSED notes under Testing.

What was changed or not taken as-is:
- The practice's skeleton is a visitor class with a method per node type.
  The pass uses one walk over children() instead, with two exceptions: the
  receiver of c(5), which the tree dump leaves out, and the closure variable
  a lambda declares, which is never removed. Without the second exception
  the loop would never stop.
- A first draft skipped lambda bodies when deciding whether the enclosing
  function has an effect. No test could tell the two versions apart, and
  counting the body only keeps more, so it was dropped for simpler code.
- The first edge-case probe used exit v + cap, which the language rejects;
  it was rewritten before any fixture was made.
- The first memory measurement used a recursive function. It was never
  removed (it calls itself, so its count stays at 1), so the note cites the
  non-recursive removals instead, and the recursion case went into the
  README as a counting limit.
