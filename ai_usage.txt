What was changed or not taken as-is:
- Practice rule change: the old error for a variable named like a function
  was removed with its unit case, because the practice allows declaring
  both and refuses only the call.
- Call results are named call.ret and loads NAME.val, so the IR matches
  the practice's excerpts. One old unit regex expected value names without
  '.'; it was widened to accept %"b.val".
- Load before getelementptr in an object declaration, to match the order
  in the practice's output.ll excerpt.
- Some first drafts of fixtures used syntax the language rejects (exit
  with an expression, a struct without fields) or looped forever; they
  were corrected before any commit, and each expected output was checked
  by hand against the program.
- Same-named lambdas in two functions first clashed in LLVM; the checker
  now names the second struct lambda.NAME.2.
- After the test-suite review, four fixtures were added for cases that had
  only been tried by hand: lambda name reuse, a callable parameter, a
  top-level variable inside a lambda in a function, and calling a capture
  from outside the lambda. The overlapping declaration and assignment
  error tests were kept because the practice lists both.
- The AI first added a Co-Authored-By line to two local commits; it was
  removed before pushing.
